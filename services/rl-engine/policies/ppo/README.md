# ppo policy

Contextual-bandit routing policy optimised with MaskablePPO (sb3-contrib) on logged Alibaba traces. Replaces the random-shadow baseline when `RL_POLICY=ppo` and `services/rl-engine/models/policy.zip` is present.

## Why "bandit" and not "RL"

The offline training simulator (`services/rl-engine/training/simulator.py`) replays trace windows independently of the agent's action — there are no environment dynamics. The trained policy is a contextual bandit (state → chosen backend) that uses PPO machinery for optimisation. See the simulator docstring for the framing rationale.

## Status

Shipped. `policy.zip` is generated by `services/rl-engine/training/train_ppo.py` and validated by the canary gates before the full run.

## Files

- `policy.py` — `PPOPolicy(RoutingPolicy)` loads policy.zip on init, falls back to uniform-shadow rankings over eligible backends if missing
- `README.md` — this file

## Operating modes

- `shadow` — full inference each cycle; `RoutingAction.mode = "shadow"`. LB sidecar ignores. Use for pre-production verification.
- `hybrid` — full inference; `RoutingAction.mode = "active"`. LB sidecar applies the weights iff every other gate agrees (see `runloop.effective_mode` + the safety-boundary section of the parent README).
- `learning` is accepted for backwards compatibility with older `policy.yaml` schemas and is treated as `hybrid`.

## Ranking shape (argmax-dominant weighting)

The Discrete(N) action space PPO was trained on chooses one backend per step. Treating its softmax over logits as a weight distribution is not what it was optimised for. The serving path instead assigns `_DOMINANT_WEIGHT` (default 0.7) to the argmax backend and splits the remaining 0.3 evenly among other eligible backends — strong preference for the policy's choice, small floor so NGINX health probing of the rest still works.

## Eligibility

Unhealthy and unknown backends are excluded from rankings via `policy_base.is_eligible()`. An "unknown" verdict means no telemetry signal arrived for that backend in the query window — we refuse to route to a backend we have no data on. When every live backend is unhealthy/unknown the policy emits empty rankings + `mode=shadow`; the anomaly detector's existing sidecar exclusions remain in effect.

## reload contract

`reload(**kwargs)` updates mutable runtime params (operating_mode, confidence_threshold, exploration_rate) in place without reloading `policy.zip` from disk. The run loop calls it on every `smartload.policy` publish; a policy republish does not pay torch's model-load cost. Artifact swap still requires a container restart.
